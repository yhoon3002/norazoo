## 5. 리스크 목록 (건드리면 안 되는 결합)

1. **현상금 카운트** (`bountyData` + turnSlice `addKill(e.template)`): 매칭 키가 template **id 문자열**이고 killCounts가 세이브에 영구 저장됨 → **id 개명/삭제 절대 금지**. 본안은 스탯만 변경하므로 안전. slime_mass ×12는 신규 slime hp 320 기준 ~6전투 분량으로 여전히 합리적.
2. **스토리 킬 게이트** (`defeated_{fieldId}_{index}` 정확 매칭): e1(2마리)·e2(3)·guardians(3)·gorge_boss(3)의 **그룹 구성/마릿수 변경 금지** — 인덱스가 어긋나면 진행 무한 정지. 본안은 구성 불변, 템플릿 스탯만 수정. RespawnController의 리스폰 키도 templates 배열 길이 기반이라 동일 조건.
3. **리트라이 경로** (BattleUI handleRetry → `startCombat({group: lastEncounterGroup})`): 그룹이 template id를 들고 있고 미지 id는 combatSlice L83-86에서 **throw** → id 불변이므로 안전. 단, combatSlice가 스탯을 조우 시작 시 원본 복사하므로 **패치 직후 리트라이하면 신규 HP로 재시작**됨(수용 가능, 세이브 마이그레이션 불필요 — hp 절대값이라 진행 중 전투 세이브만 영향).
4. **QTE 프로필** (ATTACK_PROFILES + enemyActionsSlice의 **name substring 폴백** "orc"/"slime"/"mage"): name·chargeMs·hits·parryable 전부 미변경 → 패리/닷지 윈도 및 튜토리얼 페이스(slime 1200ms 단타) 보존. 단 atk 변경은 perHit(total/hits)를 통해 QTE 실패 벌점을 바꾸므로 본안은 atk를 현행 ±2 이내로만 조정(devourer 42 유지 → 3히트 벌점 동일).
5. **exp 분배 결합** (floor(exp/aliveCount), 사망자 0): §3 총량은 3인 생존 기준 — 보스전 사망이 잦으면 lv 목표 미달 가능하므로 사이드존 여유분(~+550/인)이 버퍼. **레벨업 스탯(+10hp/+2atk/+1def/+1spd)과 초기 expToNext(캐릭터 데이터)는 변경하지 말 것** — 커브 전체가 이 값에 맞춰 설계됨.
6. **드롭 경제**: 강화 재료(orc_tusk/monster_core/dark_crystal) 확률 미변경 — orc가 스펀지에서 4-5방 엘리트가 되어 시간당 드롭이 오히려 정상화되므로 제련 재료 수급은 개선되면 됐지 악화되지 않음.
7. **scale**: gear_devourer 2.4만 존재 (EnemyMesh L229 / FieldEnemyAvatar L545) — 미변경.
